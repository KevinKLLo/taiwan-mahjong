## Context

現有引擎僅有胡牌回應者佇列、17 張暗手胡牌判斷，UI 與 AI 共用 legalActions。參見 proposal.md 與已確認對話。

## Goals / Non-Goals

Goals：保持純狀態轉移與唯一實體牌 ID，完整支援副露及回應優先權。
Non-Goals：不改 Electron 原生邊界、不計台、不加入特殊牌型。

## Decisions

- 以分階段佇列處理胡、碰槓、吃，而非按 UI 點擊速度判定。胡全過後才開放副露；同玩家可先過胡再碰。
- 每個副露紀錄類型、牌與來源。對手暗槓顯示四張牌背，不洩漏牌面或 ID；終局揭露。
- 加槓先進入可搶胡狀態，無人胡才轉換碰組並尾補。被搶時原碰組不變、第四張移給胡者。不允許搶暗槓。
- 自己摸牌後（含莊家起手）可暗槓／加槓；吃碰後僅出牌，不能把尚未摸牌的回合當作自摸或自槓。
- AI 固定先胡，再槓、碰、吃，再使用原有棄牌評分。強度不在驗收範圍。
- 舊固定回放保留原來「只摸打」策略，新增全動作守恆模擬；牌數斷言扣除每組副露佔用的三張暗手名額。

## Risks / Trade-offs

- 搶槓期間牌重複歸屬 → 等待時第四張留原手牌，確認後才搬移。
- 全過或多人回應卡住 → 有限回應佇列與完整回放測試。
- 任意 IDs 偽造吃牌 → 引擎比對完整合法組合，不只比對動作種類。
